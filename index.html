1. Реляционная модель (3-я нормальная форма — 3NF)

Ниже представлена визуальная ER-диаграмма реляционной схемы базы данных торгового отдела:

erDiagram
    customer {
        int customer_id PK
        string full_name
        string phone UK
        string email UK
        text address
    }
    product {
        int product_id PK
        string name
        string category
        numeric price
        int stock_quantity
    }
    employee {
        int employee_id PK
        string full_name
        string phone UK
        string position
    }
    orders {
        int order_id PK
        timestamp order_date
        string status
        int customer_id FK
        int employee_id FK
        numeric total_amount
    }
    order_item {
        int order_id PK, FK
        int product_id PK, FK
        int quantity
        numeric unit_price
        numeric subtotal
    }

    customer ||--o{ orders : "оформляет"
    employee ||--o{ orders : "обрабатывает"
    orders ||--|{ order_item : "содержит"
    product ||--o{ order_item : "включает"

Спецификация таблиц 3NF:

Таблица Назначение Основные атрибуты
customer Клиенты (покупатели) customer_id, full_name, phone, email, address
product Товары торгового отдела product_id, name, category, price, stock_quantity
employee Сотрудники (менеджеры) employee_id, full_name, phone, position
orders Заказы клиентов order_id, order_date, status, customer_id, employee_id, total_amount
order_item Позиции заказа (товары в заказе) order_id, product_id, quantity, unit_price, subtotal

2. Модель Data Vault 2.0 (Хранилище данных)

Архитектура хранилища сырых данных, разделенная на Хабы, Ссылки и Сателлиты:

erDiagram
    hub_customer {
        uuid customer_hkey PK
        string customer_bk UK
        timestamp load_date
        string record_source
    }
    sat_customer {
        uuid customer_hkey PK, FK
        string full_name
        string email
        text address
        timestamp load_date PK
        string record_source
    }
    hub_product {
        uuid product_hkey PK
        string product_bk UK
        timestamp load_date
        string record_source
    }
    sat_product {
        uuid product_hkey PK, FK
        string name
        string category
        numeric price
        int stock_quantity
        timestamp load_date PK
        string record_source
    }
    hub_employee {
        uuid employee_hkey PK
        string employee_bk UK
        timestamp load_date
        string record_source
    }
    sat_employee {
        uuid employee_hkey PK, FK
        string full_name
        string position
        timestamp load_date PK
        string record_source
    }
    hub_order {
        uuid order_hkey PK
        string order_bk UK
        timestamp load_date
        string record_source
    }
    sat_order {
        uuid order_hkey PK, FK
        timestamp order_date
        string status
        numeric total_amount
        timestamp load_date PK
        string record_source
    }
    link_order_customer {
        uuid link_order_customer_hkey PK
        uuid order_hkey FK
        uuid customer_hkey FK
        timestamp load_date
        string record_source
    }
    link_order_product {
        uuid link_order_product_hkey PK
        uuid order_hkey FK
        uuid product_hkey FK
        timestamp load_date
        string record_source
    }
    sat_order_item {
        uuid link_order_product_hkey PK, FK
        int quantity
        numeric unit_price
        numeric subtotal
        timestamp load_date PK
        string record_source
    }

    hub_customer ||--o{ sat_customer : "sat"
    hub_product ||--o{ sat_product : "sat"
    hub_employee ||--o{ sat_employee : "sat"
    hub_order ||--o{ sat_order : "sat"
    hub_order ||--o{ link_order_customer : "link"
    hub_customer ||--o{ link_order_customer : "link"
    hub_order ||--o{ link_order_product : "link"
    hub_product ||--o{ link_order_product : "link"
    link_order_product ||--o{ sat_order_item : "sat"
